| ID | 構成 | 必須操作 | 状態 | 証拠・問題ID |
|---|---|---|---|---|
| A11Y-WIN | Windows + 現行ブラウザ + NVDA | 読み上げ、キーボードのみ、200% | `NOT RUN` | |

## 3. 必須経路

各経路について、順序、見出し、状態通知、フォーカス、操作完了を確認します。

| F02 | L1をキーボードだけで進める | 選択、正誤、次へ、記述式自己確認を完了できる | `NOT RUN` | |

## 4. キーボードとフォーカス

- [ ] Tab / Shift+Tabで全操作要素へ到達できる
- [ ] Enter / Spaceで要素の役割どおり操作できる
- [ ] フォーカス順が見た目と意味の順序に一致する
- [ ] フォーカス表示が常に視認できる
- [ ] 画面遷移後、主見出しまたは新しい本文へ移動する
- [ ] フォーカス対象が固定要素などに完全には隠れない
- [ ] キーボードトラップがない
- [ ] 無効なボタンを無効と認識でき、次に必要な操作が分かる

## 5. 読み上げ

- [ ] 各画面の主見出しと現在位置が分かる
- [ ] ボタン、リンク、テキスト入力、チェックボックスの名前と状態が分かる
- [ ] コードと通常文を区別して読める
- [ ] 正解、誤答、ヒント、保存失敗、移行、リセット結果が一度だけ通知される
- [ ] 進捗バーの名前、現在値、最大値が意味に合う
- [ ] L10の「理解済み」と「実践済み」を区別できる
- [ ] 装飾記号や三色ドットが不要な雑音にならない
- [ ] 外部リンクの目的がリンク文脈から分かる

読み上げの発話を全文転記する必要はありません。問題箇所、期待、実際、再現手順を記録します。

## 6. 拡大、リフロー、色、タッチ

- [ ] 200%拡大で内容・操作を失わない
- [ ] 320 CSS px相当で主要経路にページ全体の横スクロールが発生しない
- [ ] コード例の局所スクロールが必要な場合、本文操作を妨げない
- [ ] 縦向き・横向きの両方で読める
- [ ] 色だけで正誤、完了、現在位置を伝えていない
- [ ] 通常文字4.5:1以上、大きな文字3:1以上のコントラストがある
- [ ] UI部品とフォーカス表示に必要な非テキストコントラストがある
- [ ] 操作対象は原則24×24 CSS px以上、または規定の例外・間隔を満たす
- [ ] OSの高コントラスト・色反転・文字サイズ設定で操作不能にならない
- [ ] タッチ操作で隣接対象を誤作動しにくい

## 7. 問題の重要度

| 重要度 | 定義 | Gateへの影響 |
|---|---|---|
| P0 | データ損失、プライバシー侵害、広範囲の操作不能 | 即時`FAIL`、公開停止を検討 |

| P3 | 表現・効率・一貫性の改善 | backlogへ記録 |
