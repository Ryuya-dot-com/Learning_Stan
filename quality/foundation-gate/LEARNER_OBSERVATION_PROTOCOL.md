# 初学者完走観察プロトコル

## 1. 目的

プログラミング未経験またはR未経験の対象学習者が、L1–L10を理解し、進捗を管理し、最後に自分のPCでRコードを再実行できるかを観察します。

これは少人数の形成的ユーザビリティ評価です。学習効果の統計的証明、個人の成績評価、医療・障害情報の調査を目的としません。

## 2. 最初の実施単位

- 最低3名、可能なら5名の適格な初学者
- 全員がL1–L10と必須転移課題に触れる
- WindowsとmacOSの両方を可能な範囲で含める
- 教材の設計・実装に直接関与した人を参加者に含めない

この人数は重大な失敗の発見と基準値作成のためのものです。達成率を母集団へ一般化しません。最初の観察値を見てから、次版の数値目標と必要標本数を決めます。

## 3. 適格条件

- 18歳以上
- Rの実務経験がない、または入門操作をほとんど行ったことがない
- 研究・学習で表形式データを扱う可能性がある
- 自由意思で参加し、いつでも中止できる

未成年者、成績評価を直接受ける学生、参加拒否が不利益になり得る人を含める場合は、この簡易プロトコルを使わず、所属機関の手続きを確認します。

## 4. プライバシーと同意

- 参加者コードは`P01`のような無作為コードにする
- 氏名、学籍番号、メールアドレス、成績、診断・障害情報を記録しない
- 録画・録音・画面共有の保存は既定で行わない
- 発話は個人を特定できない要約だけを残す
- 参加は任意で、理由を述べず中止できる
- 正式な研究、論文、学会発表へ転用する場合は、事前に倫理審査と追加同意の要否を確認する

### 読み上げる説明

> この観察は、あなたを評価するものではなく、教材の分かりにくい点を見つけるために行います。途中で止めても不利益はありません。氏名や成績は記録しません。迷ったときは、その時考えていることを話してください。助けが必要な場合は遠慮なく伝えてください。

口頭説明後、[匿名観察記録票](LEARNER_OBSERVATION_RECORD.md)の同意欄を確認します。

## 5. 実施前準備

- [ ] 対象commit SHAと公開URLを固定する
- [ ] 新規ブラウザプロファイルまたは進捗リセット済み環境を用意する
- [ ] OS、ブラウザ、R、RStudioの版を記録する
- [ ] ネットワーク、ファイル保存権限、再起動可否を確認する
- [ ] 進行役と観察者の役割を決める
- [ ] 90分を超える場合は休憩または2回への分割を用意する
- [ ] L10のパッケージ導入に失敗した場合、教材・ネットワーク・権限を区別して記録する

## 6. 進行役の規則

1. 最初は操作方法を教えず、タスクの目的だけを読み上げる。
2. 沈黙を失敗扱いせず、考える時間を待つ。
3. 支援した場合は、次の水準と時刻を必ず記録する。
4. 正解をほめて誘導せず、「そう考えた理由」を尋ねる。
5. 参加者の失敗を能力不足と解釈せず、教材・UI・環境のどこで情報が不足したかを記録する。

### 支援水準

| コード | 支援 |
|---|---|
| I | 支援なしで完了 |
| H1 | タスク文または画面をもう一度読むよう促した |
| H2 | 関連する画面・教材箇所を示した |
| H3 | 次の具体的操作またはコードを伝えた |
| F | 支援しても完了できなかった |
| B | 端末・ネットワーク・権限など外部要因で実施不能 |

## 7. 必須タスク

### T01 — 開始、移動、再開

「教材を最初から始め、途中でホームへ戻り、もう一度続きから再開してください。」

観察すること: 開始位置、戻る操作、進捗表示、再開位置、フォーカス移動。

### T02 — L1の自己説明

L1を進め、「Rは何のための言語で、コードを実行すると何が起きるか」を自分の言葉で記述し、評価基準で自己確認してもらいます。

観察すること: 例を見る前の説明、保存されないことの理解、文字を消した場合の無効状態。

### T03 — L2–L4の基礎操作

教材の演習を完了後、次のコードの結果を実行せずに説明してもらいます。

```r
scores <- c(2, 4, 6)
scores[2] * 10
```

正答だけでなく、代入、ベクトル、添字をどう説明するかを記録します。

### T04 — L5–L8の産出

教材例と異なる名前を使い、次の2点を行ってもらいます。

1. `group <- c("B", "A", "B")`を、A、Bの順のfactorに変換するコードを書く。
2. 数値ベクトルを受け取り、合計を返す関数を作って呼び出す。

構文の完全一致より、文字列・factor・ベクトル化・関数の役割を区別できるかを観察します。

### T05 — L9の転移

次の表について、欠損値を除く平均を求めるコードを書き、結果が何を表すか説明してもらいます。

```r
study <- data.frame(score = c(10, 12, NA, 14))
```

期待する中核: `mean(study$score, na.rm = TRUE)`と、対象列・欠損除外・平均の意味の説明。

### T06 — L10 Foundation Check

参加者自身のPCで次を行います。

1. RStudioを起動し、Consoleの入力待ちを確認する。
2. `1 + 1`を実行する。
3. R Scriptを作成・保存し、閉じて開き直してSourceする。
4. 学習用RStudio Projectを作り、そのProjectからScriptを開く。
5. `tidyverse`を導入し、新しいRセッションで読み込む。

Web上のチェックは、実機結果を確認した後にだけ付けてもらいます。

### T07 — 進捗の所有と復旧

「進捗を書き出し、リセットし、書き出したファイルから復元してください。」

観察すること: 警告の理解、誤操作、ファイル選択、復元結果、サーバへ送信されないことの理解。

## 8. 終了時質問

誘導しない順序で尋ねます。

1. いちばん迷った場所はどこでしたか。
2. 自力でできるようになったと思うことは何ですか。
3. 「理解済み」と「実践済み」はどう違うと思いますか。
4. 次に同じ作業をするとき、どこを見返しますか。
5. 教材に1つだけ変更を加えるなら何ですか。

満足度だけで成功を判断しません。発言は実際のタスク結果と分けて記録します。

## 9. 分析方法

- タスク別に`I / H1 / H2 / H3 / F / B`を集計する
- 事実、参加者の解釈、観察者の仮説を分離する
- 問題を内容、評価、UI、アクセシビリティ、環境、運用へ分類する
- 同じ問題が複数人で起きたかを記録する
- P0 / P1は1件でもGateを止める
- 最初の観察結果を基準値として保存し、次版の目標値は事後に理由付きで決める

2–7日後の遅延再現テストはM7で行います。Foundation Gateでは必須ではありませんが、実施した場合は直後結果と混ぜず別に記録します。
