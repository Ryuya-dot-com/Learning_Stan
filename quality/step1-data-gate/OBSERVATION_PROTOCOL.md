# L12→L13 データ品質観察プロトコル

## 1. 観察する問い

次の5点を別々に観察します。

1. CSVの読込成功を、内容の正しさと取り違えないか。
2. 分析前に必要な検査を、自分の言葉で計画・実行できるか。
3. rawを上書きせず、問題行と採用行を追跡可能に分けられるか。
4. 教材と行位置が違う未見データへ品質ルールを移せるか。
5. 「読込成功」と「品質ゲート通過」に必要な証拠を説明できるか。

正解したかだけでなく、最初の判断、実行した検査、支援水準、raw保全、説明の根拠を記録します。

## 2. 対象と位置づけ

- 最低3名、可能なら5名のR初学者
- L12を完了し、DQ01開始時点ではL13をまだ見ていない
- DQ03前にL13を通常どおり学ぶ
- 教材の設計・実装へ直接関与した人を含めない

これは少人数の形成的評価です。達成率を母集団へ一般化しません。最初のコホートでは恣意的な合格率を置かず、タスク別の基準値と再発する誤概念を記録します。

## 3. 進行役の規則

1. 各タスクの引用部分だけを読み、検査項目や関数名を先に教えない。
2. 「正しいです」「惜しいです」と反応せず、判断の根拠を尋ねる。
3. 7分間動きがない、または参加者が支援を求めた場合だけ段階的に支援する。
4. 支援した時刻・内容・水準を必ず記録する。
5. 観察した事実、参加者の説明、観察者の仮説を別欄へ記録する。
6. DQ01・DQ02が終わるまで、L13本文や進行役用採点キーを見せない。

### 支援水準

| コード | 支援 |
|---|---|
| I | 支援なしで完了 |
| H1 | タスク文または自分の出力を読み直すよう促した |
| H2 | 関連する教材ページや確認対象の列を示した |
| H3 | 次の具体的な検査・関数・操作を伝えた |
| F | 支援しても完了できなかった |
| B | 端末・ネットワーク・権限など外部要因で実施不能 |

## 4. 実施前準備

- [ ] 対象commit SHAと公開URLを固定した
- [ ] レッスン冒頭の「STEP 1一括スターターZIP」を展開し、`Learning_Stan_STEP1`を新しいRStudio Projectとして開いた
- [ ] `rt_data.csv`、`rt_data_dirty.csv`、`participants.csv`が`data/`にある
- [ ] 参加者がL13本文・`nb1-data.qmd`・`step1_analysis.R`をまだ開いていないことを確認した
- [ ] 参加者が独立転移課題の`step1-transfer.qmd`・`step1_transfer_check.R`をまだ開いていないことを確認した
- [ ] R、RStudio、dplyr、readrの版を記録した
- [ ] `tools::md5sum("data/rt_data_dirty.csv")`を進行役が記録した
- [ ] DQ04用オブジェクトはまだ作らず、DQ03終了後に採点キーどおり準備する

## 5. 必須タスク

### DQ01 — 読み込めた後の判断（L13を見る前）

参加者に `rt_data_dirty.csv` を `read_csv()` で読み込んでもらい、エラーなく表が表示された後、次だけを読みます。

> このデータを使って条件別の平均反応時間を計算してよいでしょうか。今の時点で判断し、そう考えた根拠を説明してください。

記録するもの:

- 最初の判断: `進めてよい` / `まだ進めない` / `判断できない`
- 読込成功を根拠にしたか
- 追加で必要だと述べた確認
- 最初の判断を後から書き換えていないか

ここでは関数名の知識を要求しません。「読み込めた以外の内容確認が必要」と区別できるかを測ります。

### DQ02 — 自分で検査を計画・実行する（L13を見る前）

> 分析へ進む前に必要だと思う確認を、できる範囲で実際に行ってください。何を確認したか、なぜ必要かも説明してください。

形、列型、重複、カテゴリ、値域、ID対応、欠損のうち、参加者が自発的に計画・実行したものを記録します。5種類すべての発見を合格条件にはせず、教材を見る前の基準値として扱います。単に `View()` した場合も、何を探したかを確認します。

DQ02終了後、通常のL13を最後まで学んでもらいます。

### DQ03 — raw・issue・processedを分ける（L13学習後）

> `rt_data_dirty.csv` は変更せず、問題行を記録した表と、品質ルールを通った分析用の表を作ってください。作業後に、元ファイルが変わっていない証拠も示してください。

参加者が作る成果物名は次に固定します。

- `data/processed/rt_data_issues.csv`
- `data/processed/rt_data_checked.csv`

記録するもの:

- 問題一覧が5種類を区別しているか
- checkedデータが12行か
- `tools::md5sum()`の作業前後が一致するか
- rawを直接編集・上書きしようとしたか
- 除外基準が教材用の仮ルールであると説明できるか

### DQ04 — 未見の表への転移

進行役が[準備・採点キー](FACILITATOR_KEY.md)のコードを実行し、`transfer_raw`だけを参加者へ示します。行位置は教材例と異なり、ファイルは新規作成しません。

> `transfer_raw` を上書きせず、同じ品質方針で `transfer_issues` と `transfer_checked` を作ってください。問題の種類と、採用した行数を説明してください。

記録するもの:

- L13コードをファイル名だけ変えて貼るのではなく、表オブジェクトへ適用できたか
- 5種類の問題を各1件検出したか
- `transfer_checked` が8行か
- `transfer_raw`のfingerprintが変わっていないか
- エラー時に検査結果を確認して修正したか、勘でコードを変えたか

### DQ05 — 証拠を説明する

次の2つを並べて尋ねます。

1. 「CSVはエラーなく読み込めた」
2. 「品質ゲートを通った12行を分析へ使った」

> 2つの主張には、それぞれどの証拠が必要ですか。別の研究データでも使える言葉で説明してください。

最低限記録する観点:

- 読込成功は形式・パス・構文が受理された証拠にすぎないと区別したか
- 品質ゲートには、定義したルール、問題件数、採用後の再検査、raw保全が必要だと説明したか
- 「問題が0件」と「検査していない」を区別したか

## 6. 任意の遅延課題

2〜7日後、L13を開かずにDQ04相当を再実行します。直後結果と混ぜず、`DELAYED`として別に記録します。遅延課題を実施できないことは、最初の観察を無効にしません。

## 7. 分析指標

- DQ01の最初の判断と根拠
- DQ02で自発的に計画・実行した検査
- タスク別 `I / H1 / H2 / H3 / F / B`
- raw上書きの試行と、実際のfingerprint不一致
- DQ03・DQ04の問題種別カバレッジ
- checked行数と不一致ID件数
- DQ05で残った誤概念
- 教材、UI、コード、環境、運用のどこに起因したか

## 8. 観察から修正箇所への対応

| 観察 | 最初に見直す箇所 | 追加前に確認する反証 |
|---|---|---|
| DQ01で読込成功を品質保証とみなす | L12末尾とL13冒頭の接続 | タスク文が「正しいデータ」と誤って示していないか |
| DQ02で検査を1つも計画できない | L12の読込後チェックとL13の順序 | R構文不足ではなく概念不足か |
| DQ03でrawを上書きする | ダウンロード欄、raw/processed説明、保存コード | 観察用Projectのフォルダ構成が原因でないか |
| DQ03は通るがDQ04で転移できない | L13の演習とNB1の品質ゲート | 採点キーや行位置が事前に露出していないか |
| DQ05で「問題0件」と「未検査」を混同する | `stopifnot()`と検査ログの説明 | 質問文が二択を誘導していないか |

最初のコホートの数値を見てから現版へ都合のよい合格線を追加しません。raw消失、問題入りデータの無警告分析、再現不能な除外は、人数にかかわらずP1候補として独立レビューします。
