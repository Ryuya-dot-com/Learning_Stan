# STEP 1 Data Quality Gate 実施キット

## 目的

L12からL13へ進む初学者が、「エラーなく読み込めた」と「分析に使える品質である」を区別し、rawを保ったまま問題記録と分析用データを分離できるかを形成的に観察します。

これはSTEP 1改善用の小規模な公開後フィードバック・キットです。[Foundation公開後フィードバック](../foundation-gate/README.md)の記録や、学習効果の統計的証明を置き換えません。人数の下限は設けず、得られた結果は導線上の不足を見つけ、次版の基準値を作るために使います。達成率を母集団へ一般化せず、未実施は公開・教材完成・品質判定を止めません。

## 使用する文書

- [観察プロトコル](OBSERVATION_PROTOCOL.md)
- [進行役用の準備・採点キー](FACILITATOR_KEY.md)
- [匿名観察記録票](OBSERVATION_RECORD.md)
- [コホート判断記録](DECISION_RECORD.md)

進行役は、参加者へ採点キーを見せません。原本へ結果を直接書かず、対象commit SHAと日付を含むコピーを作ります。

```text
quality/step1-data-gate/evidence/
└── SDQ-2026-08-01-<commit>/
    ├── learner-P01.md
    ├── learner-P02.md
    ├── learner-P03.md
    └── decision.md
```

## 実施順

1. 対象commit SHA、公開URL、Rと主要パッケージの版を固定する。
2. 参加者がL12を終え、L13をまだ見ていない時点でDQ01・DQ02を行う。
3. 参加者にL13を学んでもらい、DQ03を行う。
4. 進行役が未見のインメモリ表を準備し、DQ04を行う。
5. DQ05で「読込成功」と「品質ゲート通過」の証拠を説明してもらう。
6. 参加者別記録からコホート判断記録を作り、変更箇所と反証条件を残す。

## 証拠の状態

- `NOT RUN`: 未実施
- `OBSERVED`: 規定手順で観察し、事実を記録した
- `BLOCKED`: 端末・権限・時間などの外部要因で実施できなかった
- `INVALID`: 誘導、答えの露出、記録欠落などにより比較できない

ファイルが存在するだけで`OBSERVED`にしません。自動テスト成功も、初学者が区別を理解した証拠にはしません。

## プライバシーと利用範囲

- 氏名、学籍番号、メール、成績、診断情報を記録しない。
- 録画・録音・生のコンソール履歴をリポジトリへ保存しない。
- 発話は個人を特定できない要約にする。
- 正式な研究、論文、学会発表へ転用する場合は、所属機関の倫理審査と追加同意の要否を確認する。

## 完了の定義

実施キットの実装完了と、任意のフィードバック記録は別です。現時点の状態は`NOT RUN`です。記録が得られた場合は問題の重要度・所有者・再検証条件を整理しますが、対象者観察を完了扱いにすることは公開条件ではありません。
