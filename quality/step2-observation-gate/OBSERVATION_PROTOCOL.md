# STEP 2初心者観察プロトコル

## 1. 観察する問い

L17〜L20を終えたR初学者について、次を別々に観察します。

1. 試行行と分析単位を区別し、コード前に要約順序を計画できるか。
2. 問いに応じて条件内分布図と単位内対応図を選び分けられるか。
3. 対応キー、描画層、点数・線数、保存寸法を実行前に説明できるか。
4. 空のRセッションから2図・3CSV・探索メモを再生成できるか。
5. 列名と文脈を変えたデータで、標本内観察と非主張事項を分離できるか。

満足度、理解問題の正答、最終チェッカーPASSだけで判断しません。最初の計画、初回成果物、支援、エラーからの修正、図を選んだ根拠を記録します。

## 2. 対象と条件

- 最低3名、可能なら5名のR初学者
- L17〜L20を完了して2〜7日後を推奨
- STEP 2の設計・実装へ直接関与していない
- 初回提出までL17〜L20完成版Rコード、採点キー、自己チェッカーを開かない
- 自発的なR Helpと公式パッケージ文書は利用可能
- 生成AI、他者の回答、非公式な完成コードは初回提出まで利用しない
- 1名ずつ最大90分。休憩と環境停止時間は課題時間から分ける

少人数の形成的観察です。完遂率を母集団の学習効果へ一般化しません。最初の結果を見て現版に都合のよい合格点を後付けしません。

## 3. 進行役の準備

1. 対象commit SHA、教材URLまたはローカル版、実施日時、R・RStudio・主要パッケージ版を固定する。
2. 観察用ZIP生成検査とRリハーサルを実行し、配布・初回提出・採点動線を確認する。リハーサル結果は参加者証拠に数えない。
3. `participant-pack.zip`を参加者ごとの新しい場所へ展開し、そのフォルダをRStudio Projectとして開く。
4. `step2_transfer_check.R`と`FACILITATOR_KEY.md`は別フォルダに置く。
5. 開始前のraw SHA-256・MD5、384行、列名を進行役だけが記録する。
6. `output/`と`step2_transfer.R`は参加者自身に作らせる。
7. 録画・録音や生コンソール履歴ではなく、匿名記録票へ観察事実を記録する。

## 4. 支援水準

| コード | 支援 |
|---|---|
| I | 進行役の支援なし。自発的な公式文書利用を含む |
| H1 | 課題文、自分の計画、直前の出力を読み直すよう中立に促した |
| H2 | 課題票の該当節、確認対象の列、公式文書の入口を示した |
| H3 | 次の具体的な関数、対応付け、検査、修正操作を伝えた |
| F | 支援しても必須成果物または説明を完了できなかった |
| B | パッケージ、権限、端末、時間など外部要因で実施できなかった |

7分間動きがない、または参加者が支援を求めた場合にH1から順に使います。支援した時刻、実際の言葉、支援前の状態を記録します。タイプミスの指摘も支援です。

## 5. 必須タスク

### S201 — コード前の計画

課題票とCSVを示し、コードを書く前に、入力の1行、分析単位、除外位置、3CSV、2図、メモ、再生成順序を説明してもらいます。

特に、デバイス×条件の予想行数、対応線の予想本数、`high_load - baseline`の向き、図ごとの問い、非主張事項を記録します。正しい関数名の暗記だけで判定しません。

### S202 — 分析単位と3CSV

参加者が`step2_transfer.R`を作り、rawを検査し、`valid == TRUE`だけをデバイス×条件へ要約し、3CSVを保存して読み直します。

記録するもの:

- filtering前後の1行の意味と行数
- デバイス×条件の行数
- 中央値、Q1、Q3、IQRを計算する対象
- 同じdevice_idの2条件を対応付ける方法
- 差の向き
- raw fingerprintと上書きの試行

### S203 — 2図の選択と描画

全デバイス点を残した条件別分布図と、同じデバイスを結ぶ対応図を作成します。

記録するもの:

- 実行前に予測した層・点数・線数
- x、y、fill/color、groupの役割
- `group = device_id`相当が線レイヤーにあるか
- 2図の違いを参加者が説明できるか
- 色だけに依存せず、軸・点・線・文字で読めるか

### S204 — 保存・報告・クリーン再実行

2図を`ggsave()`で7×5 inch・300 dpiへ保存し、7行の探索メモを書きます。作業オブジェクトを削除し、観察用Project内の6成果物だけを別名退避または削除して、`step2_transfer.R`から再生成します。rawは削除しません。

参加者が完了を宣言した時点で、6成果物、raw MD5、空のRセッション相当からの再実行結果、完了時刻を初回提出として固定します。

### S205 — 自己チェッカー後の修正と説明

初回提出を固定した後だけ、進行役が`step2_transfer_check.R`をProject直下へコピーします。参加者が1回実行し、初回PASSまたはエラー分類を記録します。

失敗した場合、期待値を口頭で教えず、チェッカー出力と自分の中間表に基づく1回の自己修正を許可します。その後、参加者に次を説明してもらいます。

- 認知課題から再利用した判断
- デバイス文脈へ変更した判断
- 条件別分布図と対応図の役割
- 標本内で観察できたこと
- 有意差・母集団差・因果効果を結論しない理由
- 次の実データで分析前に確認する設計情報

## 6. 終了カテゴリー

- `INDEPENDENT`: S202〜S204をIまたはH1で初回提出し、rawを保ち、初回チェッカーPASS、図の役割と限界を説明
- `SELF_REPAIRED`: 初回チェッカーFAIL後、期待値提示なしの1回修正でPASSし、説明も成立
- `SUPPORTED`: H2またはH3でPASS、または主要説明が支援後に成立
- `INCOMPLETE`: 分析単位、対応、再生成、限定付き報告のいずれかが未完了
- `BLOCKED`: 外部要因で判定不能
- `INVALID`: 完成コード・採点キー・チェッカーの事前露出や誘導で初回条件が崩れた

カテゴリーは成績ではありません。S201〜S205別の支援水準と観察事実を優先します。

## 7. 修正先の切り分け

| 観察 | 最初に確認する箇所 | 追加前に確認する反証 |
|---|---|---|
| 試行行のまま分布を描く | L17の分析単位、S201課題文 | filteringや集計より前の行数表示が誤解を誘ったか |
| Q1・Q3を全測定から計算する | L17の参加者要約→条件要約 | 列名または採点キーが曖昧でないか |
| `group = load_condition`で線を結ぶ | L19の対応キー説明 | xの順序や欠測による描画問題でないか |
| 2図を同じ役割と説明する | L18→L19の比較導線 | 課題票が別々の問いを十分示しているか |
| Exportボタンだけで保存する | L20の保存契約 | `ggsave()`の構文ではなく書込権限が原因か |
| 合成標本から因果効果を結論する | L20の非主張、scenario | 「負荷」という語が因果を誘発していないか |
| 再実行で古い成果物を読む | L20の入口と出力検査 | Dropboxロックや作業ディレクトリが原因か |

## 8. 観察後

参加者別記録からコホート判断票を作り、観察事実、参加者の説明、環境証拠、競合する説明を並べます。同じ誤りが複数名でも原因を即断せず、P0・P1以外は次版で検証する変更を原則1つに絞ります。

全測定を独立単位として推測する、別デバイスを線で結ぶ、rawを失う、再現不能な手作業、合成データから因果・母集団効果を断定する問題はP1候補として独立レビューします。
